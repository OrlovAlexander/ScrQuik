# Нейронка по связкаМ1М5М10М20

Продолжение `--odds` / `*AnalyzerOdds`: те же RPM и такт M1. На вход — одна **связкаМ1М5М10М20**: **2** пачки M1 + **2** M5 + **2** M10 + **1** M20, плюс доли аналогов **связкаМ1М10** / **связкаМ5М10** / **связкаМ10М20** (цепочка 5). Не три парные связки как кадр пачек, не D1/H4/M30. Оверлей odds не развивать.

Это не `*AnalyzerMarks` и не сетапы комбо. Комбо `buy`/`sell` анализатора **не меняются**: сеть их только видит как признак вместе с числами RPM.

Исходник: [`analyzer/net.py`](../analyzer/net.py). Веса: `C:\QuikFinam\LuaIndicators\analyzer_net\net.npz`. Определения тега, пачки, связки и кадра: [tag-packs.md](tag-packs.md).

## На чём построена

Те же линии, что на живом графике QUIK. Ряд M1 — CSV barsSaver. **M5/M10/M20/M30/H4/D1 строят из этого M1** на каждой минуте (OHLC слота на этот момент). M5 и M20 — только для сети, графика QUIK нет, CSV нет. Закрытый слот фиксируют из M1 в момент закрытия; внутри слота пачка — только минуты до `t`. CSV старших ТФ — только сверка вычисленного бара **на закрытии** слота, не вход сети. Правило: [tf-from-m1.md](tf-from-m1.md).

- на каждом ТФ один RPM-current (FIR + EMA 90) и один RPM-up из `config/RPM_TF_Up_5.ini` по ТФ (M5: Mn10/Mn20/Mn30, M20: Mn30/H1/H2; графики QUIK: H4: H12/D1/W1, D1: D5/W2/W5);
- паттерн 121 на сеть не подаётся (архив, рудимент);
- теги те же: `vs0`, `vs_ema`, `slope`, `ema_vs0`, `ema_trend`, `hist_sign`, `hist_dir`;
- шкала z — медиана модуля **этого** инструмента, не чужой кусок истории.

Объекты:

- **тег** — одно свойство RPM на формирующемся баре одного ТФ;
- **пачка** — ≥5 тегов одного бара одного ТФ, такт пересчёта **M1**;
- **связка паттернов** — **связкаМ1М10**, **связкаМ5М10**, **связкаМ10М20** (доли и похожесть; те же доли — поля входа сети);
- **связка сети** — **связкаМ1М5М10М20** (пачки M1 + M5 + M10 + M20);
- **кадр сети** — на шаге M1 одна связкаМ1М5М10М20: **2** пачки M1, **2** M5, **2** M10 и **1** M20, плюс 12 чисел долей трёх пар;
- **цепочка** одного ТФ — 5 соседних баров **того же** ТФ.

Обучение: все инструменты barsSaver (сейчас 52), фьючерсы SPBFUT в выборке повторяются ×4. MLP 128×64, лосс — режим + **четыре** головы ahead, L2, ранняя остановка по balanced acc режима и ahead на хвосте каждого инструмента. Раньше **16** эпох не останавливают (`MIN_EPOCHS`), терпение **12**. Вес строки ahead — [крупный ход](#вес-крупного-хода-ahead). Головы действия нет. Базу и lift сеть не считает. На каждой минуте к кадру пачек дописывают доли аналогов трёх парных связок (`analyzer/patterns.py`): обе цепочки по 5 баров, `sim ≥ 60%`, исход — следующее закрытие старшего ТФ пары. Доли исхода у пачки или парной связки — те же три выборки, без базы/lift. `--odds` сюда эволюционировал и сам по себе не развивается.

`--train-net` без `--sec` пишет общий `net.npz`. `--train-net --sec TICKER` с нуля пишет **`net_{TICKER}_{CLASS}.npz`**, общий файл не трогает. Живой `--net` / `--watch-net` / `--watch-net-pool` читает per-sec, если файл есть, иначе `net.npz`. `--watch-net` и пул только переписывают CSV, веса не трогают.

## Что видит на входе

Такт сборки пачек — **M1**, и на истории тоже. **Кадр сети** = **связкаМ1М5М10М20** на этом M1: **2** соседних пачки M1 + **2** M5 + **2** M10 + **1** M20 (формирующаяся последняя). Соседний бар — бар **этого** ТФ. Пачки D1, H4 и M30 на вход не идут (оверлей CSV по-прежнему на графиках M1/M10/M30/H4/D1). Старшие бары из M1 на минуту кадра. Закрытый CSV внутрь слота не подставляют.

Итого на вход MLP — **7 векторов пачек** (2 M1 + 2 M5 + 2 M10 + 1 M20) плюс **12** чисел долей трёх пар: **383** (`TF_DIM=53`, `FRAME_DIM=371`, `PATTERN_DIM=12`, `IN_DIM=383`). Один прогон на минуту. Старый вход без долей (371), H1+M25+M10 (265), D1+H4+M10, 477, 306 и 204 не подходят.

На живом графике предсказание пересчитывают каждую минуту. Один вектор — один forward, четыре головы ahead. Пунктир — **одно** среднее четырёх softmax ahead (головы `Wa` нет). Круг только на **M10** — голова 10 M1, не среднее. Как из этого ставят круг — [ниже](#точка-обучение-и-живой-график).

Предвидение на истории **разное по голове**, метка не вход. **Такт строки — всегда M1** (как live). Окно — от этой минуты по ряду M1:

| голова | такт обучения | окно вперёд от этой M1 | это |
|---|---|---|---|
| 3 | каждый **M1** | **1** M1 | один M1 |
| 2 | каждый **M1** | **5** M1 | один M5 |
| 1 | каждый **M1** | **10** M1 | один M10 |
| 0 | каждый **M1** | **20** M1 | один M20 |

Смотрят high/low путь этих следующих M1 относительно close текущей минуты. Порог `ahead_flat` — медиана экскурсии **того же окна** на M1 этого инструмента × 0.25 (не шаг одной минуты). Иначе сторона с большей экскурсией. Не ждут закрытия M5/M30, чтобы положить строку в выборку. Если до правого края меньше **20** M1, строку не берут: нет долгосрочного ahead.

### Вектор одной пачки

- все числа слоёв и шаги от предыдущего бара того же ТФ, нормированные z шкалы этого инструмента: current `rpm`/`ema`/`d_rpm`/`d_ema`; small и middle `rpm`/`ema`/`hist`/`d_rpm`/`d_ema`/`d_hist`; hist `hist`/`d_hist`;
- все теги слоёв current / small / middle: `vs0`, `vs_ema`, `slope`, `ema_vs0`, `ema_slope`, `ema_trend`;
- hist: `hist_sign`, `hist_dir`;
- one-hot сетапа комбо: `none` / `buy` / `sell` / `buy1` / `sell1` / `buy2` / `sell2` / `buy3` / `sell3`;
- `miss_hist_buy` / `miss_hist_sell` — недорисованный стек без растущей hist;
- `pack_bias` — направление **пачки** (среднее голосов тегов, не один `current.vs0`);
- `layer_div_buy` / `layer_div_sell` — расхождение small/middle;
- `pack_ok` — пачка набрала ≥5 тегов.

Пачка без RPM current — нули и `pack_ok=0`. Минута без годной **текущей** пачки M1, M5, M10 или M20 в выборку не идёт.

### Доли парных связок

После 371 числа пачек идут **12** полей (`analyzer/patterns.py`). На каждую пару — `ok`, доля вверх, доля вниз, доля флета (0…1). Порядок: связкаМ1М10, связкаМ5М10, связкаМ10М20.

Аналог — история **левее** текущего слота старшего ТФ. Обе цепочки пары (по 5 пачек) с `sim ≥ 60%`. Исход хита — close старшего бара аналога против следующего закрытия того же ТФ (M10 или M20). Нет пары или нет хитов — нули (`ok=0` или доли 0). Базу и lift не пишут. Эти же доли — выборка «доля у связки», не отдельная метка ahead.

## Головы

Ствол общий (`W1`/`W2`). Режим — голова MLP (на графике её не рисуют). Предвидение — **четыре** головы по 3 класса на **одном** векторе связкаМ1М5М10М20. На строке лосс ahead только у головы этого горизонта. **Головы действия (`Wa`) нет: не учат и не рисуют.**

| выход | значения |
|---|---|
| режим | `flat` / `impulse` / `pullback` (на графике — с пачек, не softmax) |
| предвидение 1 M1 | `ahead_flat` / `ahead_up` / `ahead_down` — ближайшая минута |
| предвидение 5 M1 | то же на **5** M1 — один M5 |
| предвидение 10 M1 | то же на **10** M1 — один M10 |
| предвидение 20 M1 | то же на **20** M1 — один M20 |

**Режим на графике не из softmax MLP.** Его считают с пачек RPM: current старшего ТФ (H4, иначе M30) против M1. Старший в сторону, M1 с ним — импульс; M1 против — откат; старший у нуля — флет. На M10/M30 доли ещё усредняют внутри слота бара и сглаживают EMA (`REGIME_EMA=8`), чтобы линия не пилила 0↔100. На точку режим **не влияет**.

## Точка: обучение и живой график

**Точка** (`buy_in` / `sell_in`) — не голова MLP и не сетап комбо. Сеть учит только четыре предвидения пути. Круг на индикаторе ставят **после** прогона. `Wa` нет.

### Что учится

Разметка **не** «когда комбо buy» и **не** «2R раньше стопа за 120 M1». На минуте `t` по ряду M1 считают четыре **факта пути** (`ahead_label`):

| срок | голова | окно вперёд от этой M1 |
|---|---|---|
| минута | 3 | 1 M1 |
| M5 | 2 | 5 M1 |
| M10 | 1 | 10 M1 |
| M20 | 0 | 20 M1 |

От close минуты `t` смотрят high/low следующих M1 окна. Порог флета — медиана такой экскурсии **того же окна** на этом инструменте × 0.25 (`FLAT_FRAC`). Если обе стороны меньше порога — флет, иначе сторона с большей экскурсией. Не ждут закрытия M5/M30, чтобы положить строку в выборку.

Каждая голова ahead учится **своему** факту. На строке лосс ahead только у этой головы (тот же вектор связкаМ1М5М10М20, четыре строки на минуту). NLL этой головы умножают на [вес крупного хода](#вес-крупного-хода-ahead). Если до правого края меньше **20** M1, минуту не берут. Короткой головой строку не добирают.

Голосование четырёх фактов (сколько из четырёх окон ушло вверх / вниз / во флет) пишут в лог. **В лосс не идёт.** Этим голосованием точку на графике не ставят.

Сетапы комбо, отказ hist и расхождение small/middle — **поля вектора пачки**, не условие точки и не метка ahead.

### Вес крупного хода ahead

Это **вес строки в лоссе ahead**, не отдельная голова, не фильтр прибыли и не условие точки. Считает `ahead_move_weight` (`MOVE_WEIGHT_CAP=8`). Режим этим числом не умножают.

На минуте `t` для головы берут **тот же путь**, что и метку `ahead_label`: high/low следующих M1 окна этой головы (1 / 5 / 10 / 20).

| термин | определение |
|---|---|
| сторона вверх | `max(high) окна − close_t` |
| сторона вниз | `close_t − min(low) окна` |
| **экскурсия** | большая из двух сторон |
| **порог** | тот же, что решает `ahead_flat`: медиана экскурсии **этого окна на этом инструменте** × `FLAT_FRAC` (0.25) |

Мелочь меньше порога — метка флет, вес **1**. Ход не меньше порога:

`вес = max(1, экскурсия / порог)`, не больше **8**.

Примеры: ход ровно на границе флета → 1; в 3 раза больше порога → 3; в 8 раз и сильнее → 8. Типичный ход окна (медиана экскурсии) даёт вес около 4 (`1 / 0.25`). Потолок, чтобы один шип не забил батч.

Весом умножают только NLL **этой головы** на этой строке.

### Как из четырёх голов получают сторону (live и `--net`)

Живой кадр один раз прогоняет сеть по связкаМ1М5М10М20. Четыре головы — четыре softmax (флет / вверх / вниз) с того же вектора.

Пунктиры `ahead_up` / `ahead_down` / `ahead_flat` — равное среднее четырёх голов, **одинаковое на всех ТФ**:

`P = (голова_1 + голова_5 + голова_10 + голова_20) / 4`

Нет вектора связки — среднего нет, пунктир как флет.

Круг только на **M10** — голова **10 M1**. На M30 кругов нет. Не среднее четырёх. Правило порога то же (`action_from_ph_mean`, `ACTION_MIN=0.52`, `ACTION_GAP=0.10`):

1. Победитель — строго максимум среди флет / вверх / вниз **этой** головы.
2. Ничья или победил флет → нет точки.
3. Доля победившей стороны ≥ **52%** и на **10%** выше противоположной (вверх против вниз, не против флета).
4. Вверх → `buy_in`, вниз → `sell_in`. Выходов нет: `buy_out` / `sell_out` в CSV всегда 0.
5. **Согласие со средним.** Аргмакс головы ТФ и аргмакс среднего четырёх — одна сторона (вверх или вниз). Спор или среднее во флете → нет точки.
6. **Вето импульса.** Режим пачки с RPM (старший против M1) = импульс: не ставят `sell_in`, если старший RPM выше нуля; не ставят `buy_in`, если старший ниже нуля. На откате и флете вето нет.

Без сетапа, без вето одной чужой головы, без запасного входа.

В колонки `buy_in` / `sell_in` на **M10** пишут проценты **головы 10 M1**. Поле `action` — уже `buy_in` / `sell_in` / `none` после порога и вето. Пунктиры — среднее четырёх, не эта голова.

На **M1, M30, H4 и D1** поле `action` обнуляют: кругов нет, пунктиры остаются.

На **M10** линии слота — среднее минут внутри слота; **`action` — с последней M1 этого слота**. Круг — решение последней минуты десятиминутки, не среднее десяти решений.

Закрытый слот: mix-пунктиры не переписывают. `action` / `buy_in` / `sell_in` обновляют с текущего правила точки (голова ТФ + вето), без подстановки будущего close.

### Живой слот

`--watch-net` каждую минуту пересчитывает пачки из M1 и прогоняет сеть. Закрытые mix-пунктиры CSV **не переписывают**; живой только формирующийся слот. Точки M10 на закрытых барах пересчитывают с текущего правила (голова 10 M1 + вето), не с будущей цены. На открытом M10 точка может появиться, сдвинуться или пропасть с каждой M1 — ограничение такта, не повод подставлять закрытый бар внутрь слота. См. [tf-from-m1.md](tf-from-m1.md).

Обучение и оверлей читают последние **6000** M1 (`ODDS_MAX_BARS`). M5/M20/H4/D1 собирают из этого ряда — поэтому **новый** расчёт D1 покрывает лишь несколько последних дней. **Закрытые** строки CSV левее окна **сохраняют** (не выкидывают): иначе дневной график выглядит пустым. Закрытые mix-пунктиры внутри окна не пересчитывают; точки M10 обновляют с текущего правила. Дырка `ahead_*=0` (старый CSV без голов) при следующем `--net` заполняется заново.

### Что рисует Lua

`*AnalyzerNet` круги не считает. Читает CSV и ставит точку на уровне **33**, если график **M10**, `action` = `buy_in` или `sell_in`, и доля стороны в CSV ≥ 52 с зазором 10 к противоположной (тот же порог ещё раз). Пунктиры — три доли **среднего**. Бары **правее последней строки CSV** не заливают прошлым mix: без строки пунктир пустой (дырки внутри окна CSV по-прежнему протягивают). Чтобы край жил, нужен актуальный M1 barsSaver и `--watch-net`.

## Запуск

Нужен `numpy`. Сначала веса (`--train-net`), потом CSV для графика. Все команды анализатора: [cli.md](cli.md).

```text
python -m analyzer --train-net
python -m analyzer --train-net --sec CNY12.26
python -m analyzer --sec CNY12.26 --net
python -m analyzer --watch-net --sec CNY12.26
python -m analyzer --watch-net-pool
python -m analyzer --watch-net-pool --jobs 4
dotnet run --project tools/WatchNetUi/WatchNetUi/WatchNetUi.csproj -c Release
```

`--net` пишет CSV в `C:\QuikFinam\LuaIndicators\analyzer_net\{SEC}_{CLASS}_{ТФ}.csv` (M1/M10/M30/H4/D1). Без `--sec` — все инструменты. Читает `net_{SEC}_{CLASS}.npz`, если есть, иначе общий `net.npz`. `--watch-net` обновляет файлы по тикам M1 (окно не закрывать, простой 11 с). `--watch-net` без `--sec` идёт **последовательно** в одном процессе. `--watch-net-pool` поднимает несколько процессов `--watch-net` (по умолчанию число ядер, **не больше 8**; явный `--jobs N` при `N>0` тоже **обрезается до 8** — иначе thrash). Все тикеры в работе по шардам (`--watch-only`). Внутри шарда очередь **fair** (давно не экспортированные первыми) и **1** `export_net` за poll — иначе горячий тикер с растущим M1 голодает остальных (~60–90 с на выгрузку, до ~2 мин под нагрузкой). 52 процесса сразу дают MemoryError у numpy/OpenBLAS. `--jobs 4` — явно 4 шарда; `--jobs 0` — по процессу на тикер, если RAM позволяет. В воркерах BLAS/OMP = 1 поток. Ярлык: `tools\watch-net-pool.cmd`. GUI: [WatchNetUi](../tools/WatchNetUi/README.md) (`dotnet run … -c Release`) — тот же пул шардов, колонки возраста/ETA; не запускать вместе с CLI-пулом. После смены связки или `IN_DIM` — `python -m analyzer --train-net`. Старый `net.npz` с другой связкой не подходит. `Wa` в файле, если есть, не читают.

### Сколько стоит export

Дорогое — `instrument_samples` (пачки + аналоги) и прогон MLP по **всем M1** окна. Запись CSV M1/M10/M30/H4/D1 после этого — секунды. Отключить вывод на D1/H4/M30/M1 **почти не ускоряет**: даже один M10 строится усреднением из того же M1-ряда.

### Почему D1 «пустой»

Новый расчёт покрывает только дни внутри окна **6000 M1** (у 24h-фьючерса — несколько суток). На графике с сотнями дневных свечей пунктир виден у правого края; точки buy/sell на D1 **не рисуют** (только M10). Закрытые строки CSV **левее** окна сохраняют — история нарастает, пока пул живёт. Уже стёртое окно само не восстановит. Алиасы CNY/CR/CRZ6: Lua ищет `CR_SPBFUT_D1.csv` и `CNY12.26_…`.

## Индикатор

Скопировать [`lua/AnalyzerNet.lua`](../lua/AnalyzerNet.lua) в:

`C:\QuikFinam\LuaIndicators\AnalyzerNet.lua`

На графике **M1**, **M10**, **M30**, **H4** или **D1**:
